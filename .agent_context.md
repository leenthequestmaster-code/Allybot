# Agent Context: Allybot

## Tech Stack Summary
- **Language:** TypeScript 5.9 (ES2022, NodeNext modules, Node ≥22)
- **Runtime:** Node.js (long-running process, not web server)
- **Package Manager:** npm/bun (scripts in package.json)
- **WhatsApp Client:** Baileys (@whiskeysockets/baileys 7.0.0-rc14)
- **Local Database:** SQLite via better-sqlite3 (WAL mode)
- **Cache:** Upstash Redis (REST), @cacheable/node-cache
- **External DBs:** Supabase (economy), Neon Postgres (chat logging)
- **AI:** OpenAI SDK (xkiro AI features)
- **Logging:** Pino (structured JSON, redaction of sensitive fields)
- **Validation:** Zod 4.x (env config, API inputs)
- **Error Tracking:** Sentry
- **Build:** `tsc` → `dist/`, then `node dist/index.js`

## Core Data Flow
```
WhatsApp Socket (Baileys)
  → WhatsAppConnection (normalize, dedupe, extract)
    → MessageGateRegistry (policy filters)
      → EventBus ('message.received')
      → CommandRegistry.dispatch() (parse prefix+command, cooldown, permission check)
        → CommandMiddleware chain
        → CommandDefinition.handler()
          → Services (via ServiceRegistry.get())
          → WhatsAppConnection.sendText/sendMedia/etc.
```

## Architecture Pattern
**Plugin-based modular monolith** with clean separation:
1. **Contracts layer** (`framework/contracts.ts`): all interfaces, zero implementations
2. **Framework layer** (`framework/`): lifecycle orchestration, event bus, command dispatch
3. **Platform layer** (`platform/`): WhatsApp-specific abstractions
4. **Services layer** (`services/`): stateful business logic (each owns its own SQLite DB or external client)
5. **Plugins layer** (`framework/plugins/`): wire commands + events to services, stateless registration

## Development & Coding Rules
- **Module format:** ESM (`"type": "module"` in package.json), all imports use `.js` extensions
- **Naming:** camelCase for variables/functions, PascalCase for classes/types, kebab-case for plugin/service names
- **Error handling:** Custom `AllybotError` with category; commands catch and reply user-friendly messages; never crash the process
- **Config:** All env vars validated via Zod in `config.ts`, never access `process.env` directly outside config
- **Logging:** Pino structured logging, sensitive fields auto-redacted; use `errorMessage()` helper for error serialization
- **Testing:** `node --test tests/*.test.js` (test files not currently present in repo)
- **Build:** `tsc -p tsconfig.json` → `dist/`, start with `node dist/index.js`
- **Database:** Each service owns its own SQLite file (migrations inline via `CREATE TABLE IF NOT EXISTS` + `ALTER TABLE`)
- **Plugin pattern:** Export a factory function (e.g., `createAiPlugin()`), register commands in `load()`, listen to events in `initialize()`/`ready()`
- **Language:** UI strings and command descriptions are in Indonesian (Bahasa Indonesia)
